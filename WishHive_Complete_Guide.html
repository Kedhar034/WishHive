1. Dart Language Fundamentals

1.1 Variables & Data Types

Dart is strongly typed. We use final for values that never change after assignment, and const for compile-time constants.

// From app_theme.dart — compile-time constants
static const Color primaryAmber = Color(0xFFF5A623);
static const Color backgroundLight = Color(0xFFFFFDF7);

// From upload_service.dart — variables
bool _isUploading = false;     // Mutable variable
final task = state.first;       // Assigned once, never changed
var fileToUpload = file;         // Type inferred as File

🎯 Interview Tip

const = compile-time constant (must be known before the app runs).
final = runtime constant (set once, can be computed at runtime).
var = type inferred, mutable (use when value changes).

1.2 String Interpolation

Dart uses $variable or ${expression} inside strings.

// From contacts_page.dart
final inviteText = 'Hey $name! 🐝 Join me on WishHive';

// From image_storage_service.dart

// From upload_service.dart — complex expression
debugPrint('[UploadService] Compressed: ${file.lengthSync()} -> ${fileToUpload.lengthSync()}');

1.3 Enums

Enums define a fixed set of options. Used in HiveModel for privacy levels.

// From hive_model.dart
enum HivePrivacy { public, private, friends, specific }

// Usage — converting enum to/from String for Firestore
'privacy': privacy.name,  // Enum → String: "public"

// Parsing back from Firestore
static HivePrivacy _parsePrivacy(String? value) {
  switch (value) {
    case 'public': return HivePrivacy.public;
    case 'friends': return HivePrivacy.friends;
    default: return HivePrivacy.private;
  }
}

2.2 Factory Constructors

Factory constructors can return existing instances or transform data. We use them everywhere to parse Firestore documents.

// From wish_model.dart — Factory that parses Firestore data
factory WishModel.fromFirestore(DocumentSnapshot doc) {
  final data = doc.data() as Map<String, dynamic>? ?? {};
  return WishModel(
    id: doc.id,
    name: data['name'] as String? ?? 'No Name',
    cost: (data['cost'] as num?)?.toDouble() ?? 0.0,
    createdAt: (data['createdAt'] as Timestamp?)?.toDate(),
    ownerSeen: data['ownerSeen'] as bool? ?? true,
  );
}

🎯 Interview Tip — Why Factory Constructors?

Regular constructors ALWAYS create a new instance. Factory constructors can:
1. Parse/transform data before creating the object
2. Return a cached instance (singleton pattern)
3. Return a subtype
In our app, fromFirestore factory constructors handle type casting, null safety defaults, and data transformation.

3. Null Safety

Dart's null safety prevents null reference errors at compile time. Every variable is non-null by default.

3.1 Nullable Types (?)

// From user_model.dart
final String? username;     // Can be null
final String? photoUrl;     // Can be null
final String email;         // CANNOT be null

// From wish_model.dart
final DateTime? date;       // Optional date
final DateTime? createdAt;  // Optional timestamp

3.2 Null-Aware Operators

// ?? — Null coalescing (provide default if null)
data['name'] as String? ?? 'No Name'
user?.friendRequestsReceived.length ?? 0

// ?. — Null-safe member access
theme.textTheme.bodyLarge?.copyWith(color: Colors.grey)

// ?. with method calls
(data['cost'] as num?)?.toDouble() ?? 0.0  // Cast, then safe call

// ! — Force unwrap (use ONLY when you're 100% sure it's not null)
final uid = _uid;
if (uid == null) throw Exception('Not authenticated');
// After the check, uid is guaranteed non-null

3.3 Type Casting (as)

// From user_model.dart — Firestore returns dynamic types
final data = doc.data() as Map<String, dynamic>? ?? {};

// Safe type casting chain:
(data['quantity'] as num?)?.toInt() ?? 1
//  ↑ cast to num?   ↑ safe call  ↑ default

5. Async Programming

5.1 Future & async/await

A Future represents a value that will be available later. async/await makes async code look synchronous.

// From image_storage_service.dart
static Future<String> saveImage(File imageFile) async {
  final appDir = await getApplicationDocumentsDirectory();
  // ↑ Pauses here until the directory is fetched
  final imageDir = Directory('${appDir.path}/beehive_images');

  if (!await imageDir.exists()) {
    await imageDir.create(recursive: true);
  }

  await imageFile.copy(savedPath);
  return savedPath;  // Returns Future<String>
}

5.2 Streams — Real-Time Data

Streams emit multiple values over time. Perfect for Firestore real-time listeners.

// From firestore_service.dart — Firestore real-time stream
Stream<int> unseenFulfilledWishesCount() {
  return _wishesCollection(uid)
      .where('ownerSeen', isEqualTo: false)
      .snapshots()                        // Returns Stream<QuerySnapshot>
      .map((snapshot) => snapshot.docs.length); // Transform to Stream<int>
}

// From providers.dart — Riverpod watches streams
final unseenFulfilledCountProvider = StreamProvider<int>((ref) {
  return ref.watch(firestoreServiceProvider).unseenFulfilledWishesCount();
});

5.3 try/catch/finally & rethrow

// From upload_service.dart — Full error handling pattern
try {
  final downloadUrl = await ImageStorageService.uploadImage(file, userId);
  await FirebaseFirestore.instance.collection('wishes').doc(wishId).update({...});
} catch (e) {
  debugPrint('Upload failed: $e');
  if (task.attempt < 3) {
    // Retry logic
  } else {
    _removeFromQueue(task);
  }
} finally {
  _isUploading = false;     // Always runs, even after errors
  _processQueue();           // Continue with next item
}

// rethrow — pass the error to the caller
catch (e) {
  debugPrint('Error: $e');
  rethrow;  // Let the UI handle it
}

5.4 Firestore Transactions

// From firestore_service.dart — Atomic read-then-write
await _firestore.runTransaction((transaction) async {
  final snapshot = await transaction.get(docRef);
  final data = snapshot.data() as Map<String, dynamic>;
  final currentFulfilledBy = data['fulfilledBy'] ?? '';

  if (currentFulfilledBy.isEmpty) {
    transaction.update(docRef, {
      'fulfilledBy': fulfillerId,
      'ownerSeen': false,
    });
  }
});
// ↑ Guarantees no race conditions — if two friends click "fulfill" at the same time,
//   only one succeeds. The transaction retries automatically on conflict.

6. Design Patterns Used

6.1 copyWith Pattern (Immutability)

All our models are immutable (final fields). To "change" a value, we create a NEW object with the changed field.

// From user_model.dart
UserModel copyWith({
  String? displayName,
  List<FriendProfile>? friends,
}) {
  return UserModel(
    uid: uid,                                   // Keep original
    displayName: displayName ?? this.displayName, // Use new OR keep original
    friends: friends ?? this.friends,
  );
}

// Usage:
final updatedUser = user.copyWith(displayName: 'New Name');
// Original user is UNCHANGED, updatedUser has the new name

6.2 Repository Pattern

FirestoreService centralizes ALL database operations. Pages never touch Firestore directly.

// Service layer (firestore_service.dart)
class FirestoreService {
  Future<void> createHive(HiveModel hive) { ... }
  Future<void> updateWish(WishModel wish) { ... }
  Stream<int> unseenFulfilledWishesCount() { ... }
}

// UI layer — calls service through Riverpod provider
await ref.read(firestoreServiceProvider).createHive(hive);

6.3 Queue Pattern (Upload Service)

// upload_service.dart — Background upload queue with retry logic
class UploadService extends Notifier<List<UploadTask>> {

    state = [...state, task];  // Add to queue

8. State Management (Riverpod)

8.1 Provider Types Used

// Provider — Simple value, no state changes
final firestoreServiceProvider = Provider<FirestoreService>((ref) {
  return FirestoreService();
});

// StreamProvider — Wraps a Stream, auto-handles loading/error/data
final currentUserStreamProvider = StreamProvider<UserModel?>((ref) {
  final uid = ref.watch(uidProvider);
  return ref.watch(firestoreServiceProvider).userStream(uid!);
});

// FutureProvider — Wraps a Future
final friendFeedProvider = FutureProvider.autoDispose<List<HiveModel>>((ref) async {
  return ref.read(firestoreServiceProvider).getFriendsFeed(user.friends);
});

// NotifierProvider — Complex state with methods
final uploadServiceProvider = NotifierProvider<UploadService, List<UploadTask>>(...);

8.2 ref.watch vs ref.read

// ref.watch — Rebuilds widget when value changes (use in build())
final user = ref.watch(currentUserStreamProvider).value;
final unseenCount = ref.watch(unseenFulfilledCountProvider).value ?? 0;

// ref.read — One-time read (use in callbacks, NOT in build())
await ref.read(firestoreServiceProvider).sendFriendRequest(uid);

8.3 AsyncValue Pattern (when)

// Riverpod's AsyncValue handles Loading, Error, and Data states automatically
myUserAsync.when(
  data: (myUser) {
    if (myUser == null) return Text('User not found');
    return _buildFriendsTab(myUser);
  },
  loading: () => const CircularProgressIndicator(),
  error: (e, _) => Text('Error: $e'),
);
